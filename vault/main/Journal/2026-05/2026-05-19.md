## 22:10 — HyperAgents-inspired self-improvement subsystem landed

After studying facebookresearch/HyperAgents (Meta's self-referential self-improving agent loop), we ported the viable ideas to the vault. Four files committed in parallel via four subagents working in isolated worktrees, then cherry-picked onto main as a clean linear series.

**New files:**
- `vault/Skills/skill-versioning.md` — archive layout contract (live skill stays at `Skills/<name>.md`; history lives at `Skills/_archive/<name>/v<N>.md`; four-state machine candidate/live/archived/deprecated). Substrate everything else writes into.
- `vault/main/Routines/meta-skill-improver.md` — nightly routine (currently `enabled: false` until first manual `/run` test). Reads last 7 days of Lessons + the weekly Journal rollup, identifies skills with negative signals, drafts improved candidate versions into the archive.
- `vault/Skills/skill-staged-eval.md` — mirrors HyperAgents' `test_more_threshold = 0.4` gate. Stage-1 scores a candidate on 3 historical inputs; only candidates clearing 0.4 earn stage-2 (15 inputs). Output is a JSON score + frontmatter update.
- `vault/Skills/skill-parent-selection.md` — open-ended search à la HyperAgents' `select_next_parent.py`. Default `recency-weighted` strategy: 70% latest / 20% random non-latest / 10% best-scoring. Avoids local-optima trap.

**What's wired vs not:**
- The contract is fully specified — any routine can now archive/promote/rollback skills following `skill-versioning.md`.
- The meta-improver routine itself is INACTIVE (`enabled: false`). It must be triggered manually via `/run meta-skill-improver` first to validate behavior before scheduled runs.
- Default policy: never auto-promote. Candidates surface to Telegram for human review; user copies archive content over live to promote.

**Commits:** 7e5caf5 (versioning), 649dd91 (meta-improver), b736e86 (staged-eval), bd60d84 (parent-selection).

## 22:25 — Meta skill improver dry-run (manual)

Ran the meta-skill-improver flow by hand to validate end-to-end before enabling the schedule. Lessons folder is empty (no `Lessons/manual-*.md` files yet — the system is too new), so signals came from the W20 weekly rollup instead. W20 documents a real PinchTab single-flight race condition discovered in ai-digest-v2: when WebSearch was removed and X/Threads collectors started competing for the single PinchTab session on port 9870, navigations overwrote each other. Fix was `depends_on:` to serialize the steps.

That learning is generalizable to ANY pipeline using PinchTab — exactly the kind of cross-pollination the meta-improver should propagate to the foundational `fetch-web` skill, which previously documented PinchTab without warning about concurrency.
